Panduan Pemasangan

Sistem Order Online — untuk shared hosting dengan cPanel. Masa yang diperlukan: lebih kurang 15 minit.

1. Apa yang diperlukan 2. Tetapkan versi PHP 3. Cipta database 4. Upload fail 5. Jalankan installer 6. Cron job (wajib) 7. Selepas pasang 8. Kemas kini versi baru 9. Emel (pilihan) 10. Masalah biasa

1. Apa yang diperlukan

PerkaraKeperluan
HostingShared hosting dengan cPanel (atau DirectAdmin / Plesk — langkahnya serupa)
PHP8.3 atau lebih baru
DatabaseMySQL 5.7.8+ atau MariaDB 10.3+
DomainDomain atau subdomain sendiri, contoh order.kedaianda.com. Pemasangan dalam sub-folder (kedaianda.com/order) tidak disokong.
SSLSangat disyorkan (percuma dalam cPanel → SSL/TLS Status → AutoSSL)
Failorder-system-x.y.z.zip (versi ikut nombor)
Purchase codeKod lesen yang diberi bersama sistem, contoh QGY9-9E4Z-EWTH-DM9Z. Satu kod untuk satu domain.

Tiada SSH, Composer atau Node.js diperlukan. Semua sudah ada dalam ZIP. Jangan jalankan composer install atau npm di server.

2. Tetapkan versi PHP

  1. cPanel → MultiPHP Manager (atau Select PHP Version).
  2. Pilih domain anda → tetapkan PHP 8.3 (atau 8.4) → Apply.
  3. Jika ada Select PHP Version → Extensions, pastikan ditanda: pdo_mysql, mbstring, openssl, curl, fileinfo, dom, xml, tokenizer, ctype. Yang disyorkan: gd, intl, zip.

Installer akan menyemak semua ini dan memberitahu apa yang kurang.

3. Cipta database

  1. cPanel → MySQL® Databases.
  2. Create New Database: contoh order. Nama penuh biasanya jadi namacpanel_order — salin nama penuh ini.
  3. Add New User: contoh order, dengan kata laluan yang kuat (guna Password Generator). Salin nama penuh user dan kata laluan.
  4. Add User To Database: pilih user dan database tadi → tanda ALL PRIVILEGES → Make Changes.

Gunakan database kosong khas untuk sistem ini. Jangan kongsi dengan WordPress atau aplikasi lain.

4. Upload fail

Pilih satu cara:

Cara A — Disyorkan: subdomain atau domain sendiri

  1. cPanel → Domains → Create A New Domain (contoh order.kedaianda.com).
  2. Untuk Document Root, tulis order/public (nyahtanda “Share document root” jika ada).
  3. cPanel → File Manager → buka folder order (dicipta tadi; jika tiada folder public lagi, tak apa).
  4. Upload fail ZIP ke folder order → klik kanan → Extract. Pastikan fail seperti artisan dan folder public, app, vendor berada terus dalam order (bukan order/order-system-1.0.0/…).
  5. Padam fail ZIP selepas extract.

Cara B — Terus dalam public_html (domain utama)

  1. File Manager → public_html. Pindahkan atau padam fail lama di situ (contohnya index.html default hosting) — backup dahulu jika ada laman lain.
  2. Upload ZIP ke public_html → Extract.
  3. Tekan Settings (kanan atas File Manager) → tanda Show Hidden Files, dan pastikan fail .htaccess ada dalam public_html. Fail ini menghalakan semua permintaan ke folder public dan menyekat akses kepada fail sulit.

Jika selepas upload anda nampak halaman “The site is uploaded, but the web server needs one more setting”, server tidak membaca .htaccess. Guna Cara A, atau minta support hosting “enable mod_rewrite and AllowOverride All”.

5. Jalankan installer

Buka alamat laman anda (contoh https://order.kedaianda.com). Anda akan dibawa terus ke installer, 5 langkah:

  1. Server — semakan PHP, extension dan kebenaran folder. Semua mesti ✓ (tanda ! hanya cadangan). Jika ada ✕, ikut arahan di sebelahnya dan tekan Check again.
  2. License — masukkan purchase code anda. Kod akan diikat pada alamat laman ini. Pastikan anda membuka laman melalui alamat sebenar yang akan digunakan (contoh order.kedaianda.com, bukan alamat sementara).
  3. Database — host: localhost, port: 3306, nama database, user dan kata laluan dari Langkah 3.
  4. Your shop — nama kedai, alamat, telefon, WhatsApp, akaun super admin (emel + kata laluan anda), alamat laman dan zon masa. Tanda Add a sample menu jika mahu menu contoh untuk dicuba.
  5. Done — salin arahan cron (Langkah 6) dan semak keputusan Security check. Mesti hijau.

Selepas siap, installer dikunci secara automatik — tiada fail yang perlu dipadam. Untuk memasang semula, guna database baru.

6. Cron job (wajib)

Satu cron job yang berjalan setiap minit menghantar mesej WhatsApp kepada pelanggan, resit ke POS, membatalkan order yang tak dibayar dan menutup order yang terlupa diambil.

  1. cPanel → Cron Jobs.
  2. Common Settings: pilih Once Per Minute (* * * * *).
  3. Dalam ruangan Command, tampal arahan yang ditunjukkan di skrin Done installer — tanpa lima bintang di depan. Contoh: 
    /opt/cpanel/ea-php83/root/usr/bin/php /home/namacpanel/order/artisan schedule:run >> /dev/null 2>&1
  4. Add New Cron Job.

Penting: arahan mesti guna PHP 8.3. Perkataan php sahaja kadang-kadang menjalankan versi lama server. Laluan biasa:

  • cPanel EasyApache: /opt/cpanel/ea-php83/root/usr/bin/php
  • CloudLinux: /opt/alt/php83/usr/bin/php

Jika cron tidak berjalan, Dashboard admin akan menunjukkan amaran merah “The cron job is not running” dalam masa 5 minit.

7. Selepas pasang

  1. Log masuk di /login dengan emel dan kata laluan super admin.
  2. Settings: waktu operasi, logo, tema & warna, cara order (pickup / delivery / dine-in), SST.
  3. Products dan Categories: masukkan menu (atau ubah menu contoh).
  4. Users: akaun untuk cashier, dapur, waiter dan rider. Masing-masing log masuk dengan emel + kata laluan sendiri.
  5. Tables & QR: cetak poster Shop QR code untuk kaunter, dan kod QR meja jika ada meja.
  6. Buka /kitchen pada tablet dapur dan /pos pada telefon/tablet kaunter.

Bayaran online (FPX, kad, e-wallet) dimatikan sehingga payment gateway disambungkan (lihat bawah). Sebelum itu pelanggan bayar di kaunter.

Tiada websocket di shared hosting, jadi skrin dapur, kaunter dan tiket pelanggan dikemas kini setiap beberapa saat (bukan serta-merta). Ini normal.

Sambung payment gateway (Billplz, Bayarcash atau Stripe)

Pilih satu di Admin → Payment Gateway, masukkan kunci, dan tekan Save. Sistem terus uji sambungan dan beritahu sama ada berjaya.

  • Billplz: di Billplz, Settings → Keys & Integration → salin API Secret Key. Kemudian Billing → Collections → salin ID collection.
  • Bayarcash: di console Bayarcash, API Keys → salin Personal Access Token dan API Secret Key; Portals → salin portal key. Di checkout, FPX buka FPX, e-wallet buka DuitNow QR, kad buka kad kredit — hidupkan saluran yang sama di portal.
  • Stripe: Developers → API keys → salin Secret key (sk_live_…, bukan pk_…). Hidupkan kaedah bayaran di Settings → Payment methods. Disyorkan: Developers → Webhooks → tambah URL yang ditunjuk di halaman Payment Gateway untuk event checkout.session.completed.

Kemudian di Settings → Payment methods, hidupkan FPX / kad / e-wallet yang mahu ditawarkan.

Uji dulu dengan kunci sandbox (Billplz/Bayarcash: hidupkan suis Sandbox; Stripe: guna sk_test_…), buat satu order, dan pastikan order bertukar ke Confirmed. Kemudian tukar ke kunci sebenar.

Refund: order Stripe yang dibatalkan dipulangkan automatik. Untuk Billplz dan Bayarcash, pulangkan wang secara manual dari dashboard gateway.

Pindah ke domain lain

  1. Di laman lama: Admin → License → Move to another domain. Laman lama berhenti serta-merta.
  2. Pasang di domain baru, dan masukkan purchase code yang sama di langkah License (atau Admin → License).

Jika laman lama sudah tiada, hubungi penjual untuk melepaskan domain lama.

8. Kemas kini ke versi baru

  1. Backup dahulu: cPanel → phpMyAdmin → pilih database → Export → Go. Juga muat turun fail .env dan folder storage/app/public (gambar produk & logo).
  2. Upload ZIP versi baru ke folder yang sama → Extract → pilih untuk overwrite fail sedia ada.
    ZIP tidak mengandungi .env, jadi tetapan dan database anda kekal.
  3. Buka laman anda. Jika versi baru membawa perubahan database, skrin “Finish the update” akan muncul — masukkan emel dan kata laluan super admin → Update now. Pelanggan melihat mesej “sedang dikemas kini” sehingga langkah ini selesai.

9. Emel (pilihan)

Emel hanya digunakan untuk “Forgot password”. Secara default emel tidak dihantar. Untuk menghidupkannya:

  1. cPanel → Email Accounts: cipta contoh noreply@kedaianda.com.
  2. File Manager → buka fail .env dalam folder aplikasi (perlu Show Hidden Files) → Edit, dan ubah baris ini: 
    MAIL_MAILER=smtp
MAIL_HOST=mail.kedaianda.com
MAIL_PORT=465
MAIL_SCHEME=smtps
MAIL_USERNAME=noreply@kedaianda.com
MAIL_PASSWORD="kata-laluan-emel"
MAIL_FROM_ADDRESS="noreply@kedaianda.com"
  3. Simpan. Tiada langkah lain.

Fail .env mengandungi kata laluan database dan kunci aplikasi. Jangan kongsi, dan jangan ubah APP_KEY — semua sesi log masuk akan terputus.

10. Masalah biasa

GejalaPenyelesaian
Skrin putih atau 500 Internal Server Error selepas uploadVersi PHP domain belum 8.3 (Langkah 2). Jika masih, semak cPanel → Errors.
Halaman “The site is uploaded, but the web server needs one more setting”.htaccess tidak dibaca. Guna Cara A (document root ke public) atau minta hosting hidupkan mod_rewrite.
“The username or password was not accepted”Salah user/kata laluan database, atau user belum ditambah ke database dengan ALL PRIVILEGES (Langkah 3).
“That database does not exist”Guna nama penuh, contoh namacpanel_order.
“This database already holds tables from another program”Guna database baru yang kosong.
“This database already has a shop in it”Anda upload semula fail ke atas database lama. Tekan Reconnect and keep my data untuk sambung semula.
Security check merah di skrin DoneFail sulit boleh dimuat turun. Jangan terima order dahulu — guna Cara A atau minta hosting hidupkan .htaccess.
Gambar produk / logo tidak keluarPastikan alamat laman (APP_URL dalam .env) betul, termasuk https://.
Pelanggan tak terima WhatsApp, status POS “pending”Cron job belum berjalan (Langkah 6). Lihat amaran di Dashboard.
Laman masih di http:// walaupun SSL dipasangUbah APP_URL dalam .env kepada https://….
“This purchase code is not valid”Semak kod (huruf O dan nombor 0 tidak digunakan). Jika masih, hubungi penjual.
“This purchase code is already in use on …”Kod sudah diaktifkan di domain lain. Lepaskan di laman lama (Admin → License → Move to another domain) atau hubungi penjual.
“Could not reach the license server”Server hosting tidak dapat membuat sambungan HTTPS keluar. Minta support hosting membenarkannya.
Laman tunjuk “Temporarily unavailable”Ada masalah lesen. Log masuk di /login sebagai super admin — anda akan dibawa ke halaman License yang menerangkan sebabnya.
Lupa kata laluan super adminGuna “Forgot password” (perlu emel, Langkah 9), atau minta super admin lain set semula di Users.

Log ralat: folder storage/logs dalam aplikasi. Sertakan fail log terkini apabila meminta bantuan.
